# OdinEye — Development Log

## День 0 — Планування

### Ідея проєкту

Я хотів зробити легкий та гнучкий аналізатор IP для SOC-команд. Часто SOC-команди створюють власні інструменти для цього, тому я подумав, що буде добре зробити один зручний інструмент, у якому можна отримати всю потрібну інформацію про IP в деталях, налаштувати, що саме хочеш побачити, та отримати результат у вигляді PDF-файлу або таблиці, яку можна буде надати стороні, що запитала аналіз конкретного діапазону IP-адрес.

### Вибір джерел даних

Спочатку думав парсити сторінку [bgp.he.net](https://bgp.he.net/) для отримання даних про IP-адресу, але згодом вирішив, що це негарно, довше, і не надає весь спектр інформації, яку я хотів би бачити у своєму інструменті. Зупинився на тому, що краще отримувати дані за допомогою:

- протоколу **RDAP**
- запитів **reverse DNS**
- інструменту **Team Cymru IP-to-ASN**

### Чому вручну, а не Claude Code

Думав спочатку використати Claude Code, але вирішив, що краще зробити все вручну, щоб отримати більше знань. У цьому проєкті для мене головне — отримати більше знань про те, як влаштовані протоколи, набути більше досвіду з Python та розробкою структури проєкту, і в цілому покращити свої навички розробника.

Я розумію, що навички використання AI також важливі для прискорення роботи та більшої продуктивності, але вважаю, що junior-рівень, такий як у мене, повинен спочатку навчитися фундаментальним речам. І вже коли переходиш на senior-рівень з цим багажем знань — можеш використовувати AI для оптимізації та покращення продуктивності власної праці.

### Вибір фронтенду

Вирішив для фронтенду не використовувати великі фреймворки типу Svelte — це збільшить проєкт у декілька десятків разів, коли це непотрібно. Використовую **Flask** — невеликий фреймворк для вебзастосунків на Python.

### Структура проєкту

```
OdinEye/
├── app.py
├── templates/
│   └── index.html
└── static/
    ├── css/
    │   └── style.css
    └── js/
        └── app.js
```

Така структура тому, що Flask за замовчуванням використовує папку `templates` для методу `render_template()` при генерації вебсторінки з HTML-файлу.

> Цитата з документації Flask:
> *"Flask will look for templates in the `templates` folder. So if your application is a module, this folder is next to that module; if it's a package, it's actually inside your package."*

Так само і для папки `static` — Flask рекомендує зберігати статичні файли саме там.
